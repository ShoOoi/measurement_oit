# BLE Beacon 演習用プログラム

大阪工業大学「実世界計測」における BLE Beacon 演習（第6回〜第9回）で使用するプログラムです．  
授業では，BLE Beacon の RSSI を測定し，距離推定，誤差分析，校正，3点 Beacon による自己位置推定までを段階的に行います．

---

## 1．授業全体の流れ

| 回 | 主な内容 | 使用するもの |
|---|---|---|
| Beacon第1回 | BLE Beacon の基礎，KBeaconPro，RSSI と実距離の関係 | KBeaconPro，メジャー |
| Beacon第2回 | RSSI から距離を推定，1台→2台→3台，PCでRSSI取得 | `beacon_gui.py` |
| Beacon第3回 | 受信差，誤差，1m校正，遮蔽物，距離推定誤差 | `beacon_gui.py` |
| Beacon第4回 | 最小二乗法，グリッドサーチ，自己位置推定 | `beacon_gui.py`，`beacon_position_estimation_gui.py` |

授業では，次の流れで測定から位置推定までをつなげます．

```text
BeaconからRSSIを取得
        ↓
複数回測定して代表値（主に中央値）を求める
        ↓
1m地点の校正値 A を使って距離を推定
        ↓
3台のBeaconまでの推定距離 dA，dB，dC を得る
        ↓
最小二乗法
        ↓
グリッドサーチ または ガウス・ニュートン法
        ↓
自己位置 (x, y) を推定
        ↓
Ground Truth と比較して位置誤差を評価
```

## 2．ファイル構成

```text
.

```

### `beacon_gui.py`

BLE Advertisement を受信し，対象 Beacon の RSSI を記録する測定用 GUI です．

主な機能：

- 最大5台の Beacon を同時に指定
- Beacon ID は6桁で指定
- 時間指定による測定
- 回数指定による測定
- RSSI の生データを記録
- 受信数，最小値，最大値，平均値，中央値，標準偏差を表示
- 平均受信間隔，実測受信頻度を表示
- Beacon 発信間隔を入力した場合，受信率を参考値として表示
- 生データ CSV と統計 CSV を保存
- 受信履歴を GUI 上で確認

### `beacon_position_estimation_gui.py`

3台の Beacon の既知座標と RSSI から，PC／人の2次元位置を推定する GUI です．

主な機能：

- Beacon A，B，C の座標を入力
- 各 Beacon の1m基準RSSIを入力
- 測定地点の代表RSSIを入力
- 対数距離モデルによる距離推定
- グリッドサーチ＋最小二乗法による位置推定
- ガウス・ニュートン法による位置推定
- Ground Truth との位置誤差を計算
- 計算結果を CSV 保存

> 現在の位置推定 GUI は3台の Beacon を対象としています．  
> 4台以上の利用については最終レポートで考察しますが，現行 GUI では直接入力できません．

## 5.4 測定方法

### 時間指定

例：

```text
測定時間：30秒
```

指定した時間内に PC が受信できた Advertisement をすべて記録します．

授業では，条件を比較するときに同じ測定時間にそろえやすいため，時間指定を使用します．

例：

- 遮蔽物なし：30秒
- 人あり：30秒
- PCあり：30秒

のように条件をそろえて比較します．

### 回数指定

例：

```text
取得回数：30回
```

各 Beacon が指定件数に達した時点で測定を終了します．

3台を指定して30回に設定した場合は，

```text
Beacon A：30件
Beacon B：30件
Beacon C：30件
```

を取得した時点で終了します．

1台だけ先に30件へ到達した場合，その Beacon の余分なデータは保存せず，他の Beacon が30件へ到達するまで測定を続けます．

---

## 5.5 Beacon発信間隔

GUI の，

```text
Beacon発信間隔（参考・ms）
```

は，測定終了条件には使用しません．

例えば，

```text
1000 ms
```

と入力しても，Python が1秒ごとに1件だけ取得するという意味ではありません．

Beacon は一定間隔で Advertisement を送信しますが，

- OS
- Bluetooth アダプタ
- スキャン状態
- 無線環境
- 人体や障害物
- 複数 Beacon の同時受信

などの影響により，すべての Advertisement を PC が観測できるとは限りません．

この値は，理論的な発信回数と PC で観測できた受信数を比較するための参考値として使用します．

## 5.6 統計結果

測定中および測定後に，Beacon ごとに次の値を表示します．

| 項目 | 意味 |
|---|---|
| 受信数 | PC が実際に観測・記録できた件数 |
| 最小 | 最小 RSSI |
| 最大 | 最大 RSSI |
| 平均 | RSSI の平均値 |
| 中央値 | RSSI の中央値 |

| 実測受信頻度 | 1秒当たりに観測できた件数 |
| 受信率（参考） | 入力した発信間隔から求めた理論発信回数に対する観測数 |

### 授業で特に使用する値

本演習では主に，

```text

```

を確認します．

距離推定では，瞬間的な外れ値の影響を比較的受けにくい中央値を代表RSSIとして使用します．

# 6．位置推定プログラム `beacon_position_estimation_gui.py`

## 6.1 起動

```bash
python beacon_position_estimation_gui.py
```

---

## 6.2 入力項目

Beacon A，B，C について，次を入力します．

```text
X [m]
Y [m]
1m基準RSSI A [dBm]
測定RSSI [dBm]
```

例：

```text
Beacon A = (0, 0)
Beacon B = (4, 0)
Beacon C = (0, 3)
```

### 1m基準RSSI

第8回で各 Beacon を1m地点に置き，測定して得た中央値を使用します．

例：

```text
Beacon A：-58 dBm
Beacon B：-61 dBm
Beacon C：-59 dBm
```

### 測定RSSI

自己位置を推定したい地点で取得した RSSI の代表値を入力します．  
授業では30回程度取得した中央値を使用します．

---

## 6.3 RSSIから距離への変換

対数距離モデルを使用します．

```text
d = 10 ^ ((A - RSSI) / (10n))
```

- `d`：推定距離 [m]
- `A`：その Beacon の1m基準RSSI
- `RSSI`：測定地点で得た代表RSSI
- `n`：環境による電波減衰係数

授業では，

```text
n = 2.0
```

を基本値として使用します．

---

## 6.4 最小二乗法

候補位置 `(x, y)` から Beacon `i` までの幾何学的距離を，

```text
r_i(x,y) = sqrt((x-X_i)^2 + (y-Y_i)^2)
```

RSSIから推定した距離を `d_i` とすると，残差は，

```text
v_i = r_i - d_i
```

です．

本演習では，残差平方和，

```text
J(x,y) = Σ (r_i - d_i)^2
```

が小さくなる位置を自己位置として推定します．

3台の場合：

```text
J(x,y)
= (r_A-d_A)^2
+ (r_B-d_B)^2
+ (r_C-d_C)^2
```

---

## 6.5 グリッドサーチ

「ガウス・ニュートン法を使う」のチェックを外した状態では，グリッドサーチを使用します．

探索範囲を，

```text
X 最小
X 最大
Y 最小
Y 最大
```

で指定し，グリッド幅に従って Python 内部で候補座標を作成します．

例：

```text
X：0〜4 m
Y：0〜3 m
グリッド幅：0.1 m
```

Python が，

```text
(0.0, 0.0)
(0.1, 0.0)
(0.2, 0.0)
...
```

という候補点について `J(x,y)` を計算し，最小の候補点を推定位置とします．

> グリッドサーチのために，人が0.1mや0.5mごとに移動するわけではありません．  
> 人は測定地点で静止し，Python 内部で仮想的な候補座標を探索します．

### グリッド幅

小さいほど候補点が増えます．

例：

```text
0.5 m：候補点が少なく計算が軽い
0.1 m：候補点が多く，より細かい位置を探索できる
```

ただし，グリッド幅を細かくしても RSSI の距離推定誤差そのものが小さくなるわけではありません．

---

## 6.6 ガウス・ニュートン法

GUI の，

```text
□ ガウス・ニュートン法を使う
```

にチェックすると，グリッドサーチの代わりにガウス・ニュートン法を使用します．

ガウス・ニュートン法は，同じ残差平方和 `J(x,y)` を小さくするために，初期値から反復的に `(x,y)` を更新します．

### 初期値

現在のプログラムでは，

```text
x0 = (X最小 + X最大) / 2
y0 = (Y最小 + Y最大) / 2
```

として，入力した探索範囲の中央を初期値にします．

### グリッド幅

ガウス・ニュートン法では，

```text
グリッド幅は使用しません
```

グリッドサーチとは異なり，格子状の候補点をすべて調べる方法ではないためです．

結果には，

```text
初期値
推定位置
残差平方和 J
反復回数
収束したか
各 Beacon の距離残差
```

が表示されます．

---

## 6.7 Ground Truth

「実位置と比較する」にチェックすると，メジャー等で決めた基準位置を入力できます．

例：

```text
X = 2.0 m
Y = 2.5 m
```

推定位置を，

```text
P_est = (x_est, y_est)
```

Ground Truth を，

```text
P_true = (x_true, y_true)
```

とすると，位置誤差は，

```text
e = sqrt((x_est-x_true)^2 + (y_est-y_true)^2)
```

で求めます．

値が小さいほど，基準位置に近い推定です．

---

## 6.8 CSV 保存

候補点ごとに，

```text

residual_B_m
residual_C_m
```

主な内容：

- 校正
- 遮蔽物

### 演習1｜1m校正

を比較します．

# 10．測定時の注意

- Beacon ID を取り違えない
- Beacon の座標を記録する
- 測定中に Beacon を動かさない
- 距離はメジャーで確認する
- 比較実験では，変更する条件をできるだけ1つにする
- 同じ条件では同じ測定時間／回数を使用する
- RSSI 1回だけで距離を決めず，複数回取得する
- 受信数は Beacon の発信回数そのものではない
- 受信数が少ないことだけで Beacon の良し悪しを判断しない
- 第8回で得た1m校正値は第9回まで保存する

---

# 11．トラブル時の確認

BLE のスキャンが開始できない場合は，まず次を確認してください．

1．PC の Bluetooth が ON になっている  
2．OS で Bluetooth の使用が許可されている  
3．BLE を受信できる Bluetooth アダプタが使用されている  
4．対象 Beacon の電源が ON になっている  
5．KBeaconPro で対象 Beacon が確認できる  
6．入力した6桁 ID が正しい

# 12．授業で使用する主な用語

| 用語 | 意味 |
|---|---|
| BLE | Bluetooth Low Energy |
| Beacon | BLE Advertisement を定期的に送信する小型発信機 |
| Advertisement | 接続前に周囲へ送信する広告パケット |
| Advertising Interval | Beacon が広告を送信する時間間隔 |

| グリッドサーチ | 候補座標を格子状に評価して最小値を探す方法 |

## 補足

本プログラムは授業用です．  
BLE の RSSI は，距離だけでなく，反射，遮蔽物，人体，アンテナ，受信端末，周囲の無線環境などの影響を受けます．
